# «Четверть» — CRM для проката велосипедов и самокатов

## Постановка задачи

**Контекст.** Города всё чаще развиваются по модели «15-минутного города»:
всё необходимое должно быть в пешей или велосипедной доступности. Поэтому растёт
спрос на прокат лёгкого транспорта: велосипедов, самокатов, электросамокатов.
Сотрудникам сервиса проката нужна система, где виден весь парк транспорта:
что свободно, что у клиентов, что в ремонте и где всё стоит.

**Цель модуля 1.** Разработать веб-приложение для учёта парка транспорта
с управлением через HTML-формы.

**Сущность «Транспорт»:**

| Поле | Тип | Ограничения |
|---|---|---|
| id | целое | присваивается автоматически |
| Инвентарный номер | строка | латиница, цифры, дефис, 3–20 символов, уникальный |
| Тип | справочник | велосипед, электровелосипед, самокат, электросамокат |
| Модель | строка | обязательное |
| Статус | справочник | свободен, в аренде, на обслуживании, списан |
| Тариф | целое, ₽/час | больше 0 |
| Заряд | целое, % | 0–100, только для электротранспорта |
| Точка проката | строка | обязательное |

**Функции:**
1. Просмотр списка транспорта.
2. Добавление транспорта.
3. Редактирование транспорта.
4. Удаление транспорта с подтверждением.

**Бизнес-правила:**
- Инвентарный номер уникален в пределах парка.
- Заряд указывается только для электротранспорта.
- Все данные проверяются на сервере; при ошибке форма показывается снова
  с введёнными значениями и сообщением у неверного поля.

## Reusable UI + code

Интерфейс и код не привязаны к конкретной сущности. Сущность описывается
один раз списком полей (`entities.py`), а всё остальное строится по этому описанию:

- **форма и список** — общие шаблоны `form.html` и `list.html`, собранные из
  переиспользуемых элементов `_ui.html` (поле формы, ячейка таблицы);
- **проверка данных** — одна функция `validate` по типам и ограничениям полей;
- **хранение** — один класс `Repository`, который собирает SQL-запросы по имени таблицы и полям;
- **маршруты** — функция `make_crud` создаёт полный CRUD для любой сущности.

Сейчас так работают две сущности: «Транспорт» и «Клиент».

**Сущность «Клиент»:**

| Поле | Тип | Ограничения |
|---|---|---|
| id | целое | присваивается автоматически |
| ФИО | строка | обязательное, до 150 символов |
| Телефон | строка | обязательное, уникальное |
| Email | строка | необязательное, формат email |
| Водительское удостоверение | строка | необязательное |

### Как добавить новую сущность

1. Описать её в `entities.py` (объект `Entity` со списком `Field`) и добавить в `ENTITIES`.
2. Добавить таблицу в `schema.sql`.

Шаблоны, маршруты и SQL писать не нужно; пункт меню появится сам.

## Устройство проекта

```
app.py        — сборка приложения: для каждой сущности хранилище + маршруты
entities.py   — описания сущностей (транспорт, клиенты)
fields.py     — классы Field и Entity, универсальная проверка данных
storage.py    — универсальное хранилище для PostgreSQL
crud.py       — универсальные маршруты CRUD
schema.sql    — структура таблиц
templates/
  base.html   — общий каркас страницы и меню
  _ui.html    — переиспользуемые элементы: поле формы, ячейка таблицы
  list.html   — универсальный список
  form.html   — универсальная форма
static/       — стили
```

## Запуск

1. Установить PostgreSQL и создать базу:
   ```sql
   CREATE DATABASE rental;
   ```
2. Указать свои логин и пароль к PostgreSQL в `DATABASE_URL` в app.py
   (по умолчанию `postgres` / `postgres`).
3. Установить зависимости и запустить:
   ```
   pip install -r requirements.txt
   python app.py
   ```
   Таблицы создаются автоматически при запуске.

Открыть: http://127.0.0.1:5000
